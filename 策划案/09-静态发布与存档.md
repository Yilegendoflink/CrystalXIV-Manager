# 09 静态发布与存档

## 一份静态网页，两种托管

v0.7 随根入口一起发布整个 `界面设计稿/` 目录。Crystal 战役使用独立的存档记录和 JSON 版本 1，保留同源旧试玩槽位的读取入口；下文的 v1–v4 迁移链适用于旧三段试玩。

正式版以 HTTPS 发布。仓库根目录的 `index.html` 是入口，旧原型文件名保留为跳转入口。同一提交可用于两家平台，无构建产物依赖。Worker、渲染、音效和游戏计算都在客户端。一旦页面加载完成，模拟和本地存档在断网时可继续运行。重新访问托管网址仍需成功取得页面，也可直接使用本地 HTML。

| 平台 | 发布设置 |
| --- | --- |
| GitHub Pages | Pages → Deploy from a branch，选发布分支 `main` 和 `/(root)`。仓库根目录的 `.nojekyll` 让发布直接使用静态文件 |
| Cloudflare Pages | 导入同一仓库，生产分支设为 `main`，Framework preset 选 `None`，Build command 为 `exit 0`，Build output directory 为 `.` |

游戏和资产使用相对路径，兼容 `账号.github.io/仓库/` 和 `项目.pages.dev/`。稳定的生产网址用于日常游玩。预览部署可用新存档做验收，或导入一份从生产站导出的备份。Google Fonts 延续主动开启的可选设计。 [GitHub Pages 发布源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) · [Cloudflare Pages 静态 HTML](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/)

## 管理本地存档

试玩提供三个独立的 IndexedDB 存档槽。右上角「存档」可选择和载入槽位、导出或导入 JSON、恢复上一份。已保存内容包括炎帝陵的阵容、日期、分钟、压力、熟练度、随机数游标、最后一把与首通，以及经理发出的群消息和 H2 排班变更。本地载入后可从已结算的战斗结算后的状态继续。合约、关系网络、正式赛季与周掉落资格随长线玩法接入。

每次确认事件以事务写入完整快照，把之前一份保存为该槽的可恢复备份。存档内的修订号在事务中检查，两个标签页操作同一槽时，后来提交的旧快照会被拒绝，提醒经理重新载入。导入前验证文件结构，覆盖已有槽时提示并保留当前进度。「恢复上一份」会交换当前与上一份的进度。浏览器拒绝存储时进入临时模式，仍可导出 JSON。 [W3C IndexedDB](https://www.w3.org/TR/IndexedDB/)

浏览器按来源隔离存储。GitHub Pages、Cloudflare Pages、自定义域名、本地测试地址或另一浏览器之间，通过导出 JSON 再导入迁移。仓库子目录变化在同一来源内仍可读到同一游戏命名空间。首次正式发布后应保持生产网址稳定。清除站点数据会影响本地存档，可从此前导出的 JSON 恢复。

## 更新与兼容策略

1. 使用永久的 `game` 标识识别存档。`schemaVersion` 说明数据结构，游戏发布版本独立递增。正式存档还记录 `rulesVersion` 和内容版本，用于识别赛季内既有规则及数据。
2. 读到已支持的旧格式时，验证必要字段，在内存逐版迁移，再校验结果。整个升级与原始备份一起写入一个 IndexedDB 事务。迁移中断时保留原存档。升级前备份可以单独导出。
3. 读到更高版本或无法验证的档时提示明确原因。较旧的程序保留磁盘上的原始记录，允许导出并在相应版本打开。即便网页部署回滚，存档也保留其实际数据格式。
4. 发布新增量优先给旧档补缺省字段。角色、队伍、关卡、承诺及奖励使用稳定 ID。改显示名沿用原 ID，替换已有内容通过迁移映射，已通关和已领奖记录保留。平衡性变更依据赛季所记录的规则版本，赛季内沿用旧规则或在明确的结算点升级。
5. 发布检验至少读取上一生产版存档和最老受支持版本的样档，验证自动存档、刷新、再次推进、跨站等价导入，以及更新失败后的恢复。兼容覆盖范围与变更随版本记录。

试玩使用 `schemaVersion: 4`。`v1` 的 `payload.replacement` 与 `payload.messages` 会转成现用字段。从 `v1` 或 `v2` 读档时创建空白 `payload.duty`。`v3` 的每人每机制整数 `m` 继承为机制熟练度，生存熟练度为 `20 + round(0.4 × m)`，进攻熟练度为 `15 + round(0.6 × m)`。阵容、待进行场次、首通、随机流位置、群消息和替补安排照常继承。旧战报以原有检定数值展示，下一把启用新算法。迁移前的原始档可单独导出。

## 本次原型验收

| 用例 | 预期 |
| --- | --- |
| 从同一浏览器地址重载 | 恢复当前槽、群消息和 H2 排班。另一个槽的数据独立 |
| 更新发现旧结构 | 自动迁移为当前结构，原始 `v1` 可单独导出。后续操作保留升级前备份 |
| 文件导入 | 旧格式迁移后可继续操作。更高版本、损坏 JSON 和其他游戏的文件不会覆盖本地档 |
| 两个部署网址 | 各自管理本地槽，从站点 A 导出到站点 B 可恢复同一进度 |
| 生产副路径 | `/仓库/` 或 `/` 能加载同一静态入口和内嵌 Worker，无论是否开启 Google Fonts |
